# 🛒 TradeHub — 포인트 거래소

회원가입하고 상품을 올리고, 포인트로 사고파는 온라인 거래소예요.
HTML·CSS·JavaScript로 만들었고, 실제 서비스는 Firebase(인증·데이터베이스·서버 함수·이미지 저장소)로 돌아가요.

- **체험 모드:** Firebase를 연결하기 전에도 바로 열려요. 데이터는 그 브라우저에만 저장되고 보안이 없어서 둘러보기용이에요.
  관리자 화면은 `admin` / `admin1234`로 로그인해서 볼 수 있어요.
- **실제 서비스:** 아래 순서대로 Firebase를 연결하면 여러 기기에서 같은 계정으로 쓰고, 새로고침해도 데이터가 남아요.

## 기능

| 구분 | 내용 |
|---|---|
| 메인 | 상품 검색, 인기·신규·추천 상품, 카테고리별 목록, 고정 공지, 보유 포인트 |
| 상품 | 등록·수정·숨기기·삭제, 이미지(끌어다 놓기 지원), 이름·설명·가격·카테고리·재고, 상세 페이지 |
| 거래 | 구매 확인 창, 구매 완료 알림, 거래 기록, 중복 구매 방지, 재고 부족 차단, 포인트 안전 처리 |
| 포인트 | 가입 시 10,000 P, 구매 시 차감, 판매 시 판매자에게 지급, 포인트 내역, 실시간 잔액 |
| 회원 | 아이디·비밀번호 가입/로그인/로그아웃, 프로필, 내 상품, 구매 내역, 판매 내역, 즐겨찾기 |
| 관리자 | 대시보드, 상품 숨김·삭제, 회원 검색·정지, 포인트 지급·회수, 전체 거래·포인트 내역, 공지 작성, 테스트 데이터 관리 |
| 기타 | 즐겨찾기, 정렬(최신·인기·가격 낮은/높은·즐겨찾기), 가격 범위 필터, 거래 알림, 공지사항, 거래 검색, PC·모바일 화면 |

### 테스트 데이터와 실제 데이터 구분
- 관리자 화면 **테스트 데이터** 탭에서 가짜 상품 12개를 넣고 한 번에 지울 수 있어요.
- 테스트 상품에는 `isDemo: true`가 저장되고 화면에 보라색 **테스트** 배지가 붙어요.
- 실제 서비스에서 테스트 상품은 **구매할 수 없어요**(서버가 막아요). 진짜 포인트가 가짜 판매자에게 가지 않아요.
- 일반 회원은 `isDemo: true` 상품을 만들 수 없어요(보안 규칙이 막아요).
- 둘러보기 화면에서 **테스트 상품 숨기기**를 켜면 실제 상품만 보여요.

## 보안은 어떻게 지키나요?

브라우저에서 돌아가는 코드는 누구나 고칠 수 있어요. 그래서 **포인트와 권한에 관한 일은 브라우저를 믿지 않고 서버에서 처리**해요.

| 위험 | 막는 방법 |
|---|---|
| 내 포인트를 직접 늘리기 | 회원 문서(`users`)는 브라우저에서 쓸 수 없어요. 포인트는 Cloud Functions만 바꿔요. |
| 스스로 관리자 되기 | 관리자 목록(`admins`)은 누구도 브라우저에서 쓸 수 없어요. Firebase 콘솔에서만 만들 수 있어요. 관리자 함수는 서버가 매번 `admins/{uid}`를 확인해요. |
| 가짜 거래 기록 만들기 | `trades`, `pointLogs`, 알림은 서버만 써요. |
| 남의 상품 수정·삭제 | 보안 규칙이 판매자 본인(또는 관리자)인지 확인해요. |
| 판매 수량·즐겨찾기 수 부풀리기 | 판매자도 이 값은 못 바꿔요. 서버만 바꿔요. |
| 버튼 연타로 두 번 결제 | 구매 창마다 요청 번호를 만들고, 서버는 같은 번호를 한 번만 처리해요. |
| 마지막 1개를 여러 명이 동시에 구매 | 재고 확인·차감·포인트 이동을 하나의 트랜잭션으로 처리해서 한 명만 성공해요. |
| 구매 직전에 판매자가 가격 올리기 | 구매자가 본 가격과 서버 가격이 다르면 결제하지 않아요. |
| 잔액보다 많이 사기, 내 상품 사기, 정지 회원의 거래 | 서버가 모두 거부해요. |
| 글에 스크립트 넣기(XSS) | 화면에 넣는 모든 글자를 이스케이프하고, 이미지 주소는 `https://`만 허용해요. |

`firestore.rules`, `storage.rules`, `functions/index.js`에 규칙이 있어요.

## Firebase 연결하기 (처음 한 번)

준비물: Google 계정, [Node.js LTS](https://nodejs.org/ko) (서버 코드를 올릴 때만 필요)

### 1. 프로젝트 만들기
1. [Firebase 콘솔](https://console.firebase.google.com)에서 **프로젝트 추가**를 눌러요. 이름은 자유예요. Google 애널리틱스는 꺼도 돼요.
2. 왼쪽 아래 **요금제 업그레이드 → Blaze(종량제)** 를 골라요.
   - 서버 함수(Cloud Functions)와 이미지 저장소(Storage)는 Blaze 요금제에서만 쓸 수 있어요.
   - 매달 무료 사용량이 넉넉해서 작은 사이트는 보통 **0원**이에요. 걱정되면 Google Cloud 콘솔의 **결제 → 예산 및 알림**에서 예산 알림(예: 1,000원)을 걸어 두세요.

### 2. 로그인 켜기
**빌드 → Authentication → 시작하기 → 로그인 방법 → 이메일/비밀번호 → 사용 설정 → 저장**
(아이디로 가입하면 내부적으로 `아이디@tradehub.example` 형식의 가상 이메일로 저장돼요. 메일은 보내지 않아요.)

### 3. 데이터베이스 만들기
**빌드 → Firestore Database → 데이터베이스 만들기**
- 위치: **asia-northeast3 (서울)**
- **프로덕션 모드**로 시작 (보안 규칙은 4단계에서 올려요)

### 4. 이미지 저장소 만들기
**빌드 → Storage → 시작하기** → 같은 위치(서울) → 프로덕션 모드

### 5. 웹 앱 등록하고 설정값 붙여 넣기
1. **프로젝트 개요 옆 ⚙️ → 프로젝트 설정 → 일반 → 내 앱 → 웹(`</>`)** 을 눌러 앱을 등록해요. (Hosting 체크는 안 해도 돼요)
2. 화면에 나온 `firebaseConfig = { ... }` 내용을 복사해서 `market/js/firebase-config.js`의 `null` 자리에 붙여 넣어요.

```js
export const firebaseConfig = {
  apiKey: "AIza...",
  authDomain: "내프로젝트.firebaseapp.com",
  projectId: "내프로젝트",
  storageBucket: "내프로젝트.firebasestorage.app",
  messagingSenderId: "...",
  appId: "...",
};
```

이 값은 공개돼도 괜찮아요. 실제 보호는 보안 규칙과 서버 코드가 해요.

### 6. 보안 규칙과 서버 코드 올리기
터미널(윈도우는 PowerShell, 맥은 터미널)에서:

```bash
npm install -g firebase-tools      # Firebase CLI 설치 (한 번만)
firebase login                     # 브라우저가 열리면 Google 계정으로 로그인

cd market                          # 이 폴더로 이동
firebase use --add                 # 방금 만든 프로젝트를 고르고 별칭은 default
cd functions && npm install && cd ..
firebase deploy --only firestore:rules,storage,functions
```

`✔ Deploy complete!`가 나오면 끝이에요. 처음 배포할 때 API 사용 설정 때문에 몇 분 걸릴 수 있어요.
실패하면 1~2분 뒤에 같은 명령을 한 번 더 실행해 보세요.

### 7. 사이트 열기
- **GitHub Pages:** 이 저장소를 push하면 `https://<아이디>.github.io/board-game-party/market/` 에서 열려요.
- **Firebase Hosting(선택):** `market` 폴더에서 `firebase deploy --only hosting` → `https://내프로젝트.web.app`
- 다른 도메인에서 연다면 **Authentication → 설정 → 승인된 도메인**에 그 도메인(예: `아이디.github.io`)을 추가해 두세요.

> 파일을 더블클릭해서 `file://`로 열면 동작하지 않아요. 꼭 웹 주소(https://…)나 로컬 서버(`python -m http.server`)로 여세요.

### 8. 관리자 지정하기
관리자는 화면에서 신청하거나 얻을 수 없고, **Firebase 콘솔에서만** 지정할 수 있어요.

1. 사이트에서 관리자로 쓸 계정으로 **회원가입**해요.
2. 콘솔 **Authentication → 사용자** 에서 그 계정의 **사용자 UID**를 복사해요.
3. **Firestore Database → 데이터 → 컬렉션 시작**
   - 컬렉션 ID: `admins`
   - 문서 ID: 복사한 UID
   - 필드: `role` (string) = `admin` (필드 내용은 자유)
4. 사이트를 새로고침하면 메뉴에 **관리자**가 생겨요.

관리자를 해제하려면 그 문서를 지우면 돼요.

### 9. (선택) 테스트 상품 넣기
관리자 → **테스트 데이터 → 테스트 상품 12개 넣기**. 실제 운영 전에 **테스트 상품 모두 지우기**를 눌러 정리하세요.

## 내 컴퓨터에서 Firebase 없이 개발·테스트하기 (에뮬레이터)

Java 11 이상이 필요해요.

```bash
cd market/functions && npm install && cd ..
firebase emulators:start --project demo-tradehub
# 다른 터미널에서
python3 -m http.server 8765
```

브라우저에서 `http://localhost:8765/?emulator` 를 열면 내 컴퓨터의 가짜 Firebase에 연결돼요.
`http://127.0.0.1:4000` 에뮬레이터 화면의 Firestore 탭에서 `admins/{UID}` 문서를 만들면 관리자가 돼요.

`?demo=1`을 붙이면 Firebase 설정이 있어도 체험 모드로 열려요.

| `js/firebase-config.js` | **Firebase 설정값을 붙여 넣는 곳** |

| `firebase.json` | Firebase CLI 설정 |

## 데이터 구조 (Firestore)

| 컬렉션 | 내용 | 브라우저 쓰기 |
|---|---|---|
| `users/{uid}` | 아이디, 닉네임, 소개, **포인트**, 정지 여부, 구매·판매 수 | ❌ 서버만 |
| `users/{uid}/favorites/{상품ID}` | 즐겨찾기 | ❌ 서버만 |
| `users/{uid}/notifications/{id}` | 거래 알림 | 읽음 표시·삭제만 |
| `admins/{uid}` | 관리자 목록 | ❌ 콘솔에서만 |
| `products/{id}` | 상품 (가격, 재고, 판매 수, 즐겨찾기 수, 테스트 여부) | 판매자: 내용·가격·재고만 |
| `trades/{id}` | 거래 기록 | ❌ 서버만 |
| `pointLogs/{id}` | 포인트 변동 내역 | ❌ 서버만 |
| `notices/{id}` | 공지사항 | 관리자만 |

## 알아 둘 점
- 포인트는 사이트 안에서만 쓰는 가상 화폐예요. 현금 결제·환전 기능은 없어요.
- 아이디로 가입하기 때문에 비밀번호 찾기(이메일 재설정)는 없어요. 잊어버린 회원은 관리자가 콘솔 **Authentication**에서 계정을 지우고 다시 가입하게 해야 해요.
- 상품이 수천 개를 넘으면 목록을 한 번에 불러오는 방식이 느려질 수 있어요. 그때는 페이지 나누기를 추가하세요.
